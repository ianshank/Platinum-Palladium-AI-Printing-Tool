## Root Cause Notes for PRE-PR

### `parse_quad_invalid_content` required two iterations
The initial fix checked `if not profile.channels` — but `_post_process()` always populates
`channels` with 7 default disabled entries (K, C, M, Y, LC, LM, LK). The correct check is
`not profile.raw_sections and not profile.active_channels`, which distinguishes real .quad
content (has INI sections or non-zero curve data) from arbitrary text.

### `smooth_curve` TypeError root cause
`CurveModifier.smooth()` signature is `smooth(curve, method, strength)` — it does NOT accept
`preserve_endpoints` as a keyword argument; that's an `__init__` parameter. The server was
passing it as a kwarg, causing `TypeError` caught by try/except → HTTP 400.
